# 路由留出测试（Route Holdout）

> 用途：判断 `SKILL.md` frontmatter 的 `description` 是否会把该命中的请求放进来、把不该命中的挡在外面。
> 本文件是**留出集**——写包时不许照着它调 description，否则等于拿答案对答案。改完 description 后跑一遍，记录得分变化。

## 验证状态（如实声明）

- 用例：本文件 22 条（12 条应命中 / 10 条不应命中）。
- **语义判定未做自动化**：本机安装的 `yao-meta-skill` 只含 `references/`、`reports/`、`evals/`、`examples/`，**不含 `scripts/`**，因此 `trigger_eval.py` 不可用。B 组的「不命中」是语义判断，靠人工。
- **关键词覆盖率已自动化**：`scripts/_validate_pkg.py` 会解析本文件表格，逐条统计触发词命中情况。它只做**必要条件**检查，不做语义判定：

```bash
python scripts/_validate_pkg.py
```

- 判定口径：
  - **A 组覆盖率 < 1 → 记为问题**。这方向是真危险：应命中的请求在 description 里一个触发词都找不到，说明路由面有缺口。
  - **B 组覆盖率 ≥ 1 → 只提示，不记为问题**。关键词证明不了语义排除；把「含范畴术语」当成「会误命中」会造成假可信，因此只提示人工确认。

## 实测结果（2026-10-11，22 条全解析）

- **A 组缺口 0 条** —— 12 条应命中请求全部匹配到触发词，路由面无缺口。
- **B 组提示 4 条**，逐条确认如下，均由「材料 + 范畴术语」双条件中的**材料条件不成立**或 description 的排除项挡住：

| 用例 | 命中的词 | 为什么不命中 |
| --- | --- | --- |
| B3 教我什么是伴随函子 | 函子 / 伴随 | 无材料输入 + description 显式排除「范畴论入门教学」 |
| B4 证明 Yoneda 引理 | Yoneda | 无材料输入 + 显式排除「数学证明推导」 |
| B5 用范畴论重构我的 Python 代码 | 范畴论 / 范畴 | 显式排除「代码重构」 |
| B9 写一份关于范畴论的读书报告 | 范畴论 / 范畴 | 无材料输入（是主题写作，材料不是输入） |

> 仍不得把本文件当作「路由语义已验证」的证据。已验证的是「路由面覆盖」，未验证的是「语义排除」。

## 边界结论

- `description` 里显式写了四类排除（普通摘要 / 翻译 / 入门教学 / 证明推导 / 代码重构），B 组靠这行挡住。
- 「材料 + 范畴术语」双条件同时出现才命中，任缺其一不抢。这是本路由的核心规则，改动前先跑 A/B 两组。
